V2 is the only variant whose identity, title and thread controls land at the same offset on all four windows. V1's seam is worth keeping, but only as a quiet rule that marks where reserved space ends, not as a hard boundary that pushes the whole left cluster inward on a Mac.

The recommended bar

all four windows, thread open

Identity and navigation stay left of the OS zone, because nothing else can live there. The title and its actions sit in the centre band. The right cluster holds only the global pair, which is the part that has to dodge the captions on Windows and the left-side decorations on Linux.

The same bar, narrow

680px window

The centre band is the first thing to give up width. The title truncates, the working badge keeps its dot and drops its word, and the two global buttons never move. Nothing jumps sideways when the window is resized.

States the bar has to survive

no thread, idle, long title

How it is built

traffic-light.ts unchanged
The inset stays a padding

trafficLightInsetStyle() already returns the right declaration per platform. The recommendation changes nothing about it: the header still receives padding-left on macOS and padding-right on Windows and Linux.

The centre stops being absolute

Today the centre is a flex child that centres itself. In the recommendation the leading cluster and the trailing cluster are the flex items, and the centre is measured from the bar's midpoint with a max-width cap, so the two edges cannot fight over it.

One overflow rule instead of many

A single container query drops the text labels first, then the git chip's counts, then the spec label. Everything that disappears is reachable from the thread menu, so the bar never loses a capability.

Linux left is a real case

Ubuntu and several GNOME themes put close on the left, so --os-left and --os-right are both possible. The recommendation handles it because the leading cluster is anchored to the left inset, not to the window edge.

One decision to confirm. Whether identity sits outside the traffic lights on macOS (lights, then mark) or inside them. Outside keeps the mark at the window's corner, which is where a user looks for the app name; inside keeps the lights alone at the corner, which is what every native Mac app does.
