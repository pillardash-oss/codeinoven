Variant 7

V7 · Fixed spine

One column of chrome on the leading edge: mark, name, back and forward, then the view's own actions. A single rule closes it, and the thread title starts exactly there. The action slot reserves room for three buttons whatever the view registers, and that is the only fixed width in the column, so a view with one action and a view with three put the title on the same pixel without leaving a gap in front of the rule.

Flush, both edges The bar runs to the window edge the OS left free, with no trailing gutter. macOS is flush right, Windows and Linux-right are flush left, and only the OS zone itself is reserved. A 4px float off your own window edge reads as a panel inside a frame, not as a title bar.

Four window geometries

flush, and the column never moves

macOS reserves 80px for its traffic lights and the bar is flush to the right edge. Windows reserves 138px for its captions and the bar is flush to the left edge. A Linux desktop gets either, following gtk-decoration-layout, and the spine is flush against whichever edge is free. Nothing is added beyond the reservation itself.

The width is held

one action, three actions, idle

The reason the action slot is reserved rather than fitted: the title must not move when a view registers a different number of actions, or when the thread gains a working badge. Three frames below have one action, three actions and no working state, and the title starts on the same pixel in all of them. The rest of the column takes its own width, so macOS with a short "cio" mark carries no leftover space in front of the rule.
